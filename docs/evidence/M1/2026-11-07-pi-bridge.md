# T037 · Pi approval bridge

On 7 November the actual pinned Pi 1.4.0 SDK loaded the Amun extension, first on its own and then alongside the staged Firstmate watcher. The proof used a private Unix socket, a scoped SQLite database, the SDK tool pipeline and Pi’s Code Mode sandbox. Deterministic tool calls supplied the inputs. No provider credentials or network writes were needed.

- Direct and Code Mode nested calls to a fixture write tool were intercepted. Its read-only annotation did not confer authority. The write counter stayed at zero.
- All six Amun tools executed. Governed requests created pending records and attention items. The database contained zero approvals. These diagnostic requests cannot be claimed for external execution.
- A replacement MCP command caused a conflict notification. A service handler exception blocked the tool. Both agent lifecycle events reached the service.
- Source and packaged Electron tests exercised startup with the bridge handshake required for readiness. The proof establishes the bridge in the service-owned Pi runtime. The later Firstmate conversation composer has a separate delivery gate.

Run `pnpm test:pi-bridge` after staging the runtime and building the SQLite dependency for Node. An optional positional argument to `node scripts/pi-bridge-proof.mjs` selects the staged candidate worktree for the coexistence test.
