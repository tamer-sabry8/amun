What we asked for vs. what Amun does today

Your requirements, “Amun stories, backlogs and sprints” (the Gitex journey you approved on 20 November), checked line by line against Amun on main today, in plain words. The companion page “Idea → done” shows each step’s screen.

The short answer

1. The middle of the journey is mostly built, but tested on one tool only. Turning a PRD into stories, planning a sprint by dragging stories, and publishing to Azure DevOps all exist. Jira works for publishing. Linear breaks: Amun lost the plan.

2. Several promised pieces are missing: the “receipt” telling the chat what was created, a sprint that lives only in Amun, changing a story’s status from the sprint, and linking sprints to the Roadmap.

3. The biggest gap is outside the requirements. They stop when a sprint closes. Nothing in them, and so nothing in Amun, covers release → stories Done → epics closed → PRD done → Roadmap shows it finished. That is the end-to-end flow you asked for today, and it was never specified.

5 · The part nobody wrote down

Your requirements end at “close the sprint”. These steps were never specified, so they were never built.

Never asked

Release links to its stories

What’s needed

A release says which stories it ships. It can’t be scheduled while they aren’t done.

Today

The release card (Readiness → Verified live) stands alone. You can release with 0 of 0 stories done.

“Going live” doesn’t finish anything else.

Never asked

Epics close by themselves

What’s needed

When all of an epic’s stories are done, the epic closes, in Amun and in the tool.

Today

Epics are only titles. No “4 of 4 done”.

You can’t see which big pieces are finished.

Never asked

PRD / feature marked Delivered

What’s needed

When every epic is closed and the release is live, the PRD and the feature show Delivered.

Today

A PRD is Draft or Approved, never Done. This is your “how do I make Draft into Done” question.

Nothing ever says “this feature is finished”.

Never asked

Roadmap moves to Done

What’s needed

The Roadmap tile shows progress from its epics and moves to Done when the feature is delivered.

Today

Tiles never move on their own.

The Roadmap is a wish list, not a live picture.

What I recommend

The root cause in one sentence: Amun keeps each piece of work as a separate record and never connects them. The fix is to connect them into one chain, then let progress flow up the chain.

Idea→PRD (approved version)→Epics→Stories→Sprint→Release→Roadmap item

Dashed = the link that’s missing today.

Write the missing end of the requirements first

Add a short spec for release → stories Done → epics closed → PRD Delivered → Roadmap Done, in the same style as the Gitex one, and approve it. Otherwise we keep building screens with no agreed finish line, which is the problem you described.

Size: one page, for you to approve. No code.

Connect the chain inside Amun

Every story remembers its epic and its PRD version; every sprint, release and roadmap item remembers its stories. All later steps depend on this.

Size: medium, data only, no new screens.

Let a sprint live in Amun

Build “Keep this sprint in Amun” with a Done tick on each story. Then Mira, Invoiced and Gitex can run end to end without any tool, and the same screens work when a tool is connected.

Size: medium. Needs one before/after for your approval.

Fix the two publishing holes

Stop Linear plans being lost (PR #66), and send the receipt back to the chat with every new story ID.

Size: small. No new screens.

Let progress flow up

Story Done → epic progress → release readiness (blocks release until done) → PRD Delivered → Roadmap tile moves. Use the existing cards and add a progress line, nothing new in the prompt box.

Size: medium. Needs one before/after for your approval.

Prove it with one real run

Take one product (Badge Desk, already in Jira) from approved PRD to Delivered on the Roadmap, on your Mac, and record each screen. Only then do the same for Linear and Azure DevOps.

Size: one acceptance session.
