# Preview proposal v2: stress test — 2026-11-06

Decision: adopt one isolated preview plus explicit external-browser handoff. No Connected Browser, agent CDP/MCP gateway, cookie transfer, UA spoofing, or embedded federated sign-in workaround. The user confirmed a focused M0 and explicitly moved signing/notarization/clean-account release acceptance to a later release gate. Those release checks have not passed. The user's continuous-work instruction supersedes the proposal's STOP/continue checkpoints.

## Corrections required before implementation

1. **OAuth continuity:** opening the intercepted authorization URL in Chrome is not guaranteed to work: initiating session cookies/state/PKCE may belong to Amun's isolated profile. Prefer reopening the original app/login entry point externally and restarting auth there. Never promise Chrome sign-in will authenticate Amun. POST bodies cannot be reconstructed by opening a URL. Magic links can have the same profile-binding issue.
2. **Coverage claims:** a host list cannot guarantee detection of every federated provider, custom tenant domain, embedded widget, or same-origin proxy. State the supported rules precisely. Do not label unobserved Vercel/Cloudflare flows tested. Unknown protected previews need an explicit Open externally action. Azure DevOps remains API-only in Amun and Edge-only for company web access.
3. **Navigation gaps:** Electron programmatic loadURL/history paths require explicit policy checks; event listeners alone do not cover all paths. Subframe redirects must remain subframe decisions. Deduplicate notifications across events. Handoff IDs must be bounded, short-lived, window/navigation-scoped, invalidated on close/navigation, and usable only from the trusted shell main frame. Opening must require a user click, with global as well as per-URL throttling. Never log auth query strings.
4. **Do not regress hardening:** existing policy rejects URL credentials and non-loopback HTTP. The proposed allow examples weaken both. Preserve these restrictions. Keep all permissions denied for M0, including fullscreen/clipboard exceptions. Do not allow arbitrary about: or custom protocols before their secure adapters exist. Rule configuration must not remove mandatory IdP restrictions; validate host/path rules and default browser names consistently.
5. **Local-file security (later):** URL normalization can erase traversal before a handler sees it. Validate original requests and every decode boundary; prevent symlink-swap/TOCTOU escapes and non-regular files. An extension allowlist and canonical capability-scoped workspace mapping are required; a secret-name denylist is insufficient. Consider origin separation, cross-workspace reads, HTML form/frame/navigation and remote-image exfiltration, MIME mismatch/SVG, PDF viewer behavior/range requests, decompression/pixel limits and cancellation. Fail-closed CSP may intentionally prevent active HTML prototypes; use dev servers for those.
6. **Annotation security (later):** an isolated JavaScript world separates JS globals, not the shared DOM or all observability. Do not claim page invisibility. Cross-origin frames, shadow DOM, zoom/DPR/scroll, focus/keyboard access, and navigation races require real tests. Snapshot screenshot/marks/URL against one navigation identity. Screenshots may contain secrets despite URL redaction; require review before sending. Quote all page-derived fields (including selectors/URLs), escape delimiters, limit total payload, strip image metadata, and keep attachments private with retention/deletion rules. Prompt-injection labels are not a security boundary.
7. **Scope/dependency mismatch:** the current foundation has no production conversation/attachment pipeline or document preview. Annotation card delivery would pull later work into M0. The user chose to retain this work for later. No OpenCode backend is authorized by its mention in the proposal.
8. **Testing:** fakes establish policy, not Chromium enforcement or real auth persistence. Keep source and packaged Electron integration tests, real first-party login/restart evidence and external-launch evidence distinct. Static string scans are supplementary, not proof against obfuscated/aliased calls. Pure path policy should not perform realpath; the adapter supplies verified canonical paths. Missing coverage tooling must be configured, not assumed. Do not reproduce Google rejection merely to rediscover an already documented failure.

## Read-only repository discovery

- `apps/desktop/src/browser.ts`: installBrowser owns the view and persistent per-product session; close/window shutdown destroys it. No preview preload. `security.ts` supplies sandbox/contextIsolation=true, nodeIntegration=false, webSecurity=true. Extra preferences deny insecure content and webviewTag.
- Existing partition: `persist:amun-browser-${product}` in `browser-policy.ts`; preserve it. Request/check/device permissions deny all; downloads are denied. Popups all denied. will-navigate, will-redirect and will-frame-navigate currently enforce scheme/URL policy; did-fail-load reports bounded status. Programmatic loadURL is validated by browserCommand.
- Forbidden-pattern scan of owned apps/packages found no UA override, cookie access, preview script injection or external opener. Main shell loadFile is trusted app content, not user file preview. No local-file protocol, annotation implementation, Markdown renderer, attachment store or preferred-browser setting exists.
- Renderer is a minimal TypeScript foundation, not the later React/product shell. IPC validates trusted sender/main frame; pages receive no service port. Vitest 5.1.0, Playwright 1.64.1, TypeScript, ESLint and Prettier exist; coverage thresholds are not configured in vitest.config.ts.
- No new live Google/SSO spike performed. Existing user-observed Google rejection is evidence; full hostname redirect chains, protected Vercel and Cloudflare deployments remain unobserved. No invented SSO-wall defaults or successful auth claims.
- Future annotation recommendation: trusted overlay plus fixed isolated-world lookup and capturePage, after its actual interaction/privacy threat model is implemented. No preload or debugger gateway needed for M0.

## Focused M0 acceptance

Retain browser hardening and existing local prototype proof. Add validated mandatory IdP rules, main/subframe/popup/programmatic navigation tests, explicit safe external restart of authentication, bounded shell-only handoff IDs, and real source/package tests. Verify a controlled direct-login session persists after full app restart and is isolated from another product. Such a controlled proof establishes first-party persistence, not arbitrary-provider/SSO compatibility. Production annotation/files/composer delivery remain later work.
