1. Small-project checklist & handover receipt (Item 6)

What it enables: when a Project is too small to need a full Azure DevOps sprint board (for example a 4-step booth setup or client handover), you can tick off the scoped tasks with their owner and due date right inside the Project's side panel and record client acceptance.

2. Production release & launch tracking (Item 16)

What it enables: track a release from readiness to verified live production with strict evidence gates — linking the work area, the Roadmap release item, and the originating chat request reference (amun-r-…), while preventing "Verified live" unless the exact target commit/artifact is running in production and passes its smoke check.

Today (Roadmap release groups without live deployment or smoke verification)

Roadmap · Release R1.4 (Today)

Planned

Today Roadmap groups items by release name and target date, and Sprints tracks story states (To do, In progress, Done). There is no production release state machine, artifact SHA binding, smoke check gate, rollback record, or release-owner receipt when a story is done in Azure DevOps but not yet verified live in production.
