# Crew and terminal acceptance

On 9 November the packaged arm64 app dispatched real Codex and Claude workers through Firstmate into disposable Amun-owned worktrees. After quitting and relaunching Amun, the test compared the independent process IDs and process start times with the pre-restart observations. Both workers survived intact. The hierarchy and list showed the workers, status counts, and verified endpoints. The selected agent panel's worktree matched the independently read endpoint receipt. A missing receipt was recovered against the running worker and a repeated dispatch left the original worker in place. Firstmate's bearing records supply current work, decisions, next actions and history; the regression checks attribution and unknown endpoints.

The worker terminal opened read-only. After the PM took control, the app verified the tmux client mode. A direct SQLite read confirmed one control handoff attributed to the PM and the selected worker. The PM returned the terminal to read-only. The audit callback test initially failed, then passed after the control grant was logged. The first source run could not enable terminal control because its native module had not been rebuilt. The passing packaged run used the Electron-native module and took 1.8 minutes.

When the Electron release download returned HTTP 504, the packager used the checksum manifest bundled with the pinned Electron npm dependency to verify the cached official binary.
