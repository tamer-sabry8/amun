## Screen and interaction contract

The captain communicates with one Firstmate through Pi. Firstmate delegates using registered roles and receives their reports through the existing Firstmate channels. Preserve the Firstmate code and repository. Chats belong to Amun project or product folders. Opening another screen does not by itself create another conversation.

Represent captain interactions as prompts to Firstmate, with the approved planning exception: stage planning gestures locally and send a single combined instruction only on submission. Each navigation click sends its own read-intent prompt to Firstmate. Record the click and the exact prompt sent in activity details only. Do not insert a navigation message into a conversation. It cannot authorize a provider write. For chat review, typing edits the proposed wording in place; Update draft sends the completed revision. Keep the selected provider destination, affected record identities, approved edits and originating request reference available to the action. Attach results to the exact request. Return unknown or unmatched reports through the existing Firstmate channel. Never infer a match from title, time or the currently open screen.

Use Firstmate’s existing intake, operational backlog, parent channel, role reports and crew observation paths. Keep delivery stories in the selected tracker and planning drafts in Amun. Creating a project establishes its workspace and chat folder; staffing is independent. For current status, read the current permitted tracker record or label the cached read with its last successful refresh. A linked PRD provides planning evidence. Keep an unmatched report available through the existing channel and retain the request’s last confirmed state.
