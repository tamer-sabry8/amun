## What Was Diagnosed & Fixed Today (25 November 2026)

### Root Causes Found in the 25 Nov Ontology Traces

Unzipping `amun-trace-2026-11-25T04-49-13-024Z.zip`, `04-52-56-801Z.zip`, and `05-03-57-083Z.zip` alongside the Pi session transcript revealed:

1. **Dropped attachment (`Ontology - Nasaq_v1.docx`):** `<Composer>` on Home/Portfolio had no `onPick` handler, so it kept only filename strings and discarded the `File` objects. `app.tsx` also skipped `routeNewWork` whenever `files.length > 0`, falling back to `IntakeCard` (`choose_work`), which called `onOpen(id, pending.text)` without forwarding files (`documentIds: []`). Firstmate received no attachment and therefore dispatched zero secondmates.
2. **No way to change Project ↔ Product:** `update-area` did not accept `type`, and `{"do":"convert"}` / `convert-task` only converted `Initiative (task) → Project`.
3. **Internal container leaked onto Home & Portfolio:** `Chat with Firstmate` (`generalConversationName`, stored as `type: "task"`) appeared as an `Initiative · Work` card under `Home → Your work` and `Portfolio` because `homeModel` and `areasInScope` did not filter it out.
4. **Trace zip truncated newest turns:** `redaction.ts` slices strings at 1,000,000 characters from the start, so serializing the full `first-mate/steps.json` array cut off today's turns and produced invalid JSON.
5. **Navigation read intents leaked into chat steps drawer:** Read-only navigation inspection rows (`Open What happened for Ontology…`) showed inside the chat's `Working on` / `recent steps` drawer instead of staying in Activity only (Rule 19).

### Phase 1 — PR #78 (Merged `5c2fea2`, commit `ef0d80e`)

- **Attachment preservation from Home & Portfolio (`composer.tsx`, `attachments.ts`, `home.tsx`, `screens.tsx`, `app.tsx`, `work-session.tsx`):**
  - `Composer` now keeps actual `File[]` objects when `onPick` is omitted and passes them as `picked?: File[]` to `onSend`.
  - `app.tsx` no longer skips `routeNewWork` when files are attached, so _"Create a new product named Ontology"_ with an attached file creates a **Product** immediately and forwards `firstFiles` to `WorkSession`.
  - `IntakeStep` / `IntakeCard` preserve `pickedFiles` across `ask_group`, `choose_work`, and `define_objective`.
  - `useAttachments` updates its ref synchronously in `add`/`remove` so `WorkSession` immediately extracts attached files via `work-attachment`, saves them to Library (`documentIds`), and includes `[Attached file: …]` on Firstmate's first turn.
- **Chat steps drawer hygiene (`work-session.tsx`):**
  - Excludes read-only navigation inspection prompts from `running` and `steps` in the chat drawer while preserving them in the Activity rail (Rule 19).
- **Trace export tail preservation (`amun-rpc-handler.ts`, `amun.test.ts`):**
  - Added `serializeRecentSteps(steps, maxChars = 900_000)` so `first-mate/steps.json` stays valid JSON under the 1M-char redactor cap and always retains the newest turns.

### Phase 3 — PR #81 (Merged `106e97f`, commit `7a0a549`)

- **Live Firstmate working status across navigation (`amun-ui/src/rebuild/firstmate.ts`, `work-session.tsx`, `amun-ui/tests/firstmate-inflight.test.ts`):**
  - Root cause: `WorkSession` previously kept `busy` in local `useState(false)`, so navigating away (e.g. to Agents or Home) and returning while Firstmate was still initializing (`fm-session-start.sh`) reset `busy` to `false` and hid the `Firstmate is working…` status.
  - Added observable in-flight tracking (`startInFlight`, `setInFlightPhase`, `finishInFlight`, `inFlightState`, `observeInFlight`, `useInFlight`, `formatElapsed`) while keeping `inFlight` (`Set<string>`) backward-compatible.
  - Wired `onPhase` (`"starting"` → `"Starting Firstmate…"`, `"working"` → `"Firstmate is working…"`) and a quiet elapsed counter after 10 seconds (e.g. `(3m 41s)`) into the existing `.rb-working` status line — zero new UI chrome and no eager Pi spawn (preserving Home's 500 MiB memory budget).
