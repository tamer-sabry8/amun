**Final execution plan · 24 November 2026**

Start with the Markdown viewer, the existing Stories, Backlog and Sprints panes, and the existing tracker review. Prove an entire PM journey with those surfaces before adding a component.

This plan sequences the 24 November **Amun and Firstmate Implementation Plan** and the proposed **Firstmate drives, Amun shows** canvas work. It retains the former’s editable-story and verified-receipt requirements. The 15 scenarios below are the coverage target. Each is explicit about what a Markdown implementation delivers and what needs a separate design.

**Persistence.** Firstmate owns private playbooks and working files. Amun keeps durable, versioned Library snapshots and the app’s chat links and approvals. The crew’s authorized source revision is identified in handoff evidence. A delivered snapshot is what the captain saw and approved. A change to a Markdown source goes through a new correlated delivery and version review. There is no background folder synchronization in the first release. Amun keeps artifacts required after worktree cleanup in its existing durable store. An authorized reference transfer must prove full readable content and recovery before relying on it.

**Smallest change order.** Prefer Firstmate’s Markdown instructions, then current Amun payloads and views, then a small correction in an existing boundary. Keep new components, dependencies, migrations, protocol frameworks and additional UI tools out of the initial implementation. For each proposed change, record the failed acceptance case, the existing path reused and the files actually needed.

**Structured display.** Continue to use the existing fenced `amun` reply channel. Amun publishes the display vocabulary from its own checkout. Firstmate sends a `document` payload for a saved result or a `show` action for a supported pane. Use native shapes for stories, plans and receipts. IDs are supplied or resolved by Amun from trusted context. Model output cannot set app authority, target an arbitrary filesystem path or supply a UI component name outside the catalogue. An immediate show can open a split pane only while the originating chat is active. A late delivery files its link and respects the open view, unread state and reading position. A Library click is neutral local navigation.

## 3. How to execute and stop

Start **Phase 0 only**. At the end of **every** phase, finish that phase’s evidence, report its result, then stop and wait for the captain’s explicit go-ahead. A go-ahead advances exactly one phase. Report gates as passed, failed, blocked or deferred. Record a specific reason for each result and label packaged, controlled-transport and fixture evidence. Complete independent work _inside the current phase_ if a live prerequisite is blocked. A fixture pass cannot substitute for a required live pass. A blocked phase can advance only on an explicit decision that identifies the outstanding gate, and a dependent change still waits for its prerequisite. Worker completion cannot advance the phase.

Use a separate branch and worktree off the verified main. Keep Firstmate source, vendor pin, personal homes, sessions, worktrees, credentials and configuration under their current ownership. Preserve the existing provider permissions. This handoff gives implementation scope within the approved phase. External publication or provider changes, push, PR creation, merge, personal-home policy messages, and visible changes each require applicable authority. Keep PR #10 closed. Use existing persistence and dependencies. If a checked requirement cannot fit the existing storage, report the evidence and propose a separately reviewed minimal append-only migration.

**Agent swarms.** Use up to three workers per named batch where the execution harness supports them. The lead gives each worker the exact base, input files, concrete outputs, write ownership, test command and phase stop. Assign disconnected edits to separate worktrees with local-only delivery. Run overlapping store changes as sequential edits by one owner. Let the lead integrate and validate the combined diff. In Firstmate, use native scoped crew briefs and parent-channel reporting. Amun sends only to primary Firstmate. A test swarm may use fake transport and local fixtures, while live crew acceptance must use the isolated native fleet. If the harness has fewer slots, preserve the same tasks in smaller batches. No lane receives credentials or delegated release authority.
