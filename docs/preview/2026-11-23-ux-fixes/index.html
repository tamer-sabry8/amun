Proposed rule: “unblock goes to the chat the agent is working for”

  1. If the blocked agent’s work carries a request reference, the unblock message goes to the chat that made that request, with the same reference.
  2. If the agent is working on several requests, it goes to the chat of the one it is blocked on (the one in “Now doing”).
  3. If no request is known, it goes to General’s most recent chat, never to whatever chat happened to be open.
  4. The button says where it will go before you click, and offers Open that chat after. Firstmate’s answer and any question also show in the Island.
  5. Watch stays as it is. You still never talk to the agent directly.
A · The agent’s request chat (recommended)The answer sits next to the work it is about, with its reference.
B · Always GeneralSimple and predictable, but the answer is separated from the work.
C · Ask me each timeA small chooser of chats when you click. The most control, but an extra step each time.

Proposed life of a card

1 · Appears

Under the reply that made or changed it, not pinned to the bottom of the chat.

2 · One per document

A new save becomes a new version of the same card (“version 3”), never a duplicate card.

3 · Chip

Documents: Draft · Approved · Done (fix 1). Releases keep their stage. Checklists show “2 of 5 done”.

4 · Folds away

When set to Done, or a release reaches Verified live, it folds into “Done (n)” after a day.

5 · Always findable

Every document stays in the Library. Older replies still open the exact version they made.

Empty documents made by New document show no card until they have content. Existing duplicate “Release v1.0” documents are shown as one card with their versions; nothing is deleted.
